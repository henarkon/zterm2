## Result

Application Development arm64 zterm2 0.1.1 construite, identifiant org.henarkon.zterm2. Préférences, sockets et services de trousseau distincts ; mise à jour Sparkle amont désactivée, associations de documents et URL retirées. Export/import reste dans le répertoire propre du fork. Les cibles Makefile install, backup-old-iterm et restart sont refusées avant leurs prérequis ; aucun remplacement de l’iTerm2 installé.

Kitty : filtrage géométrie et zRange avant préparation, purge conservée, couleur Core Image sur file Metal séparée. Pool borné à 4 textures / 64 Mio incluant les ressources utilisées ; UUID, rétention jusqu’à fin GPU et drain différé. Nouveau parcours activable uniquement avec ZTERM2_KITTY_GPU=1. Attente GPU synchrone encore présente.

Reconstruction effective des dépendances natives avec Xcode 27.2 / 27B52 et Rust 1.99.1. Sources SFSymbol générées amont conservées. Composant Metal Apple requis installé. Les binaires reconstruits restent locaux, distincts du patch de sources.

Suivi stable : lecture bornée de l’appcast officiel final_modern.xml, rejet des versions non stables et XML non sûr, séparation détection / intégration / qualification. Référence stable observée 3.7.7, commit e0025340b49a2fc6415f490d77bbead5d3e0583e ; base du fork master 8bf82e4296b25a56c31a29784cd6ff547a98e819. Aucun téléchargement installateur automatique.

## Qualification

26 tests Python réussis ; 32 tests natifs ciblés réussis (crop, copie/sélection, espace de noms trousseau) ; 36 cas couleur GPU sRGB/P3/profil écran, RGB et alpha, erreur maximale 1/255. Drain, budget, tailles et rétention jusqu’à fin GPU passent sur le banc partagé. Les trois cibles Makefile interdites refusent aussi en simulation, une cible indépendante reste disponible.

Quatre essais applicatifs A/B/B/A, mêmes pixels synthétiques 640×360, 80×25 cellules, source sRGB opaque, 30 trames/s. Stabilisation 7 s, préchauffage 1 s, 90 trames mesurées sur environ 3 s ; 120 trames acquittées par essai. Garde externe : 512 Mio/processus et 20 s, empreinte physique échantillonnée toutes les 50 ms, temps Mach converti. Producteur observé séparément ; aucune attribution exclusive WindowServer/GPU.

CPU ancien parcours : 41,01 et 42,06 % d’un cœur ; nouveau GPU : 42,02 et 44,75 %. Empreinte terminal maximale dans la fenêtre mesurée : ancien 237,14 et 276,14 Mio ; GPU 343,13 et 339,39 Mio. Pool GPU observé : 1–2 textures, 0,94–1,88 Mio. Aucun gain CPU démontré ; surcoût mémoire avéré pour cette scène. Les acquittements ne prouvent pas la cadence de présentation physique.

Empreinte pixels : ba80b04943ca66a77ddaf5412219fa949f8dbe0f8e7ae41d352b4b461254453e. Profil ICC écran : 150403b7ad52e51c3fe35813f147dc2a71220e5e48e88811feee91eda5cd7446, identique entre essais et qualification couleur.

Artefacts : dist/v0.1.1, application ZIP non notarisée, candidate.patch depuis 281695ed61cb5200c13832d8f6de1d65c2cb66da, provenance, licences et mesures JSON, rapport français. v0.1.0 conservée. Export déclaratif final Cardo : ece95c7bcf59d68c888bb25b270840aa3ab3ea39871481052befe4431f75f764 ; ne vaut pas qualification d’intégration. Vérification et consolidation primaire réalisées séparément par le helper CPS avant annonce de livraison.

## Limits and incidents

Essais initiaux diagnostiques exclus du comparatif : ancien partage mémoire au mode incorrect sur Apple Silicon corrigé (argument variadique explicite), placements Kitty accumulés corrigés par remplacement p=1, suites restaurées évitées par suites de mesure uniques. Zéro objet partagé restant à la fin des quatre essais acceptés. Une mesure ajoutée ensuite au producteur n’est pas rétroactivement présentée comme observée.

Application de développement ; comparaison des deux chemins du même fork, pas comparaison avec iTerm2 officiel Release ni Battle of Yavin. Défilement/crop/masquage en pixels réels et latence/presentation restent à élargir. Les tests natifs ont réussi, mais l’absence de variante instrumentée n’est pas revendiquée. Ni production ni intégration Cardo/Vigil qualifiées. Aucun projet pair modifié, aucune MR/PR amont, aucun correctif fonctionnel commité ou envoyé ; session propriétaire toujours active.

## Recommended next action

Profiler le coût réel Core Image et l’attente synchrone, réduire le contexte/mémoire avant toute activation par défaut, puis comparer de nouveau sous mêmes gardes et étendre les contrôles visuels applicatifs. Conserver les quatre mesures acceptées comme référence, les scripts de reproduction et les releases immuables.
