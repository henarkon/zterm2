API et intégration
L'hôte importe uniquement le module public ZTermEmbedded ; copier le runtime
Frameworks/Resources/XPCServices et les helpers selon integration.txt, avec les
liens symboliques des frameworks. Les ressources utilisent encore le bundle
principal de l'hôte : examiner collisions de noms et de classes moteur.
Préparer le runtime une seule fois, avec une suite propre commençant par
org.henarkon.zterm2.embedded. Toutes les opérations/callbacks sont sur le thread
principal. Lancer l'enfant avec exécutable, argv, environnement et cwd explicites.
L'environnement du shell interactif n'est pas hérité. Garder le contrôleur
jusqu'à closed, sans bloquer la runloop. requestStop est asynchrone/idempotent.
Le code de sortie réel 75 est conservé ; le SDK ne relance pas automatiquement.
Attendre closed puis créer une nouvelle instance si la politique Cardo le demande.
Une fermeture ne doit jamais arrêter Vigil/OpenCode ou un autre processus partagé.
Les commandes métier GUI/TUI doivent passer par un canal structuré Cardo, pas
par lecture d'écran, injection de touches ou protocole métier ajouté au SDK.
